Every key is checked before an MCP tool opens

The guard — a security layer between the AI and the MCP tools it uses — checks four things on every step.

1
Is this key real, and does it open this tool? If not — blocked.
2
Out of time or budget? Each key counts down, then stops.
3
Handing work to a sub-agent? Its key must be narrower — the guard rejects any that isn't.
4
A receipt records who did what, for whom, at every step.

Why it's safer

A hijacked agent can't reach past its task

Most agents today hold broad, standing access — compromise one and it can reach far past the job it was given. A narrow security key limits the damage to what the agent is allowed to do.

The honest catch

It limits the damage

A scoped key bounds what a hijacked agent can reach — it doesn't stop the hijack. Blocking the manipulation has to happen upstream, before the agent is compromised.

The limited-key idea isn't new — a 1994 language called Telescript enforced exactly this with a credential it called a Permit. Today's agent stack is only now catching up.
